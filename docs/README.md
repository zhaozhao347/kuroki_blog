# 文档索引

这个项目有四份文档，按「读的人是谁」分工，内容不重复。

| 文档 | 位置 | 给谁看 | 回答什么 |
| --- | --- | --- | --- |
| **README.md** | 根目录 | 刚拿到项目的人 | 怎么跑起来？东西都在哪？ |
| **AGENTS.md** | 根目录 | 改代码的人 / AI 助手 | 改之前必须知道哪些约束？ |
| **DEVELOPMENT.md** | 根目录 | 想理解设计意图的人 | 为什么这么写？踩过什么坑？ |
| `docs/` | 这里 | 需要专题说明时 | 单点问题的深入说明 |

### 该读哪份

```
想跑起来              → README.md
要改代码 / 加功能      → AGENTS.md（先读，尤其 §4 hero 与 §6 陷阱清单）
要理解为什么这么设计    → DEVELOPMENT.md
想知道以后做什么        → DEVELOPMENT.md 末尾的「灵感池」
```

### 三份根文档的边界

- **README** 只讲「事实」：命令、目录树、路由表、内容存在哪个数组里。
  它**不解释原因**，也不用维护踩坑记录。
- **AGENTS** 只讲**约束与陷阱**：写之前扫一眼，避免重复踩。
  它的信息密度最高、语气最直接（「必须」「绝不要」）。
- **DEVELOPMENT** 讲**来龙去脉**：架构意图、模块边界、踩坑的完整过程。

> ★ 若文档与代码冲突，**以代码为准**，并顺手更新文档。
> 文档基线日期见各文件开头。

### `docs/` 里放什么

只放**专题**说明 —— 即「塞进上面三份会显得突兀」的内容。比如：

- 某个模块的完整数据流图
- 一次较长的性能/兼容性调查结论
- 设计参照的整理（规则、数值、出处）
